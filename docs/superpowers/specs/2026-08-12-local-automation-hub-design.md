# Local Automation Hub 설계

## 1. 목표

Windows 11에서 `CapsLock + Space`로 호출하는 AutoHotkey v2 통합 단축키 허브를 만든다. 허브는 카카오톡 보안 로그인, 문구·프롬프트 입력, 업무 모드 실행, 창 정렬, 파일 정리를 하나의 명령 팔레트로 제공한다.

핵심 성공 기준은 다음과 같다.

- 비밀번호가 소스, 설정, 로그, 클립보드에 평문으로 남지 않는다.
- 각 자동화가 독립 모듈이며 한 모듈의 실패가 전체 허브를 중단시키지 않는다.
- 파일 변경은 미리보기와 명시적 확인 후에만 실행된다.
- 사용자가 설정 파일만 편집해 문구와 업무 모드를 확장할 수 있다.

## 2. 범위

### 포함

1. `CapsLock + Space` 명령 팔레트와 숫자·검색 실행
2. 자주 쓰는 기능의 직접 단축키
3. Windows 자격 증명 저장소 기반 카카오톡 로그인·계정 전환
4. 제목·태그 검색 기반 문구와 프롬프트 입력
5. 앱·폴더·웹사이트를 묶은 업무 모드 실행
6. 현재 창 좌우·전체 배치와 모니터 이동
7. 탐색기에서 선택한 파일의 날짜 접두사 변경과 `YYYY\MM` 분류
8. 최근 파일 정리 작업 1회 되돌리기
9. 시작 프로그램 등록·해제, 진단, 비밀정보 제외 로그
10. 프로젝트 로컬 하네스와 QA 체크리스트

### 제외

- Sandboxie를 이용한 카카오톡 다중 동시 실행
- 카카오톡 메시지 읽기·전송·수집
- 비밀번호를 설정 파일이나 `.ahk`에 저장하는 기능
- 폴더, 숨김 파일, 시스템 파일의 자동 이동
- 사용자 확인 없는 파일 변경
- 네트워크 서비스나 별도 GUI 프레임워크

## 3. 선택한 접근법

모듈형 AutoHotkey v2 허브를 사용한다. 단일 대형 스크립트보다 기능 경계와 실패 격리가 분명하고, PowerShell 중심 구조보다 키보드·창 제어가 직접적이다. PowerShell은 Windows 자격 증명 저장소 연동처럼 운영체제 기능이 필요한 제한된 보조 작업에만 사용한다.

```text
Local Automation Hub
├─ Command Palette
├─ Kakao Module
├─ Snippets Module
├─ Workspaces Module
├─ Window Manager Module
└─ File Organizer Module
```

## 4. 구성 요소와 계약

### 4.1 명령 팔레트

- `CapsLock + Space`로 연다.
- 명령 이름과 태그를 검색하거나 숫자 키로 실행한다.
- 명령 등록 정보는 ID, 표시 이름, 태그, 실행 함수, 위험 수준을 포함한다.
- 한 명령의 예외를 포착해 사용자에게 알리고 허브는 계속 실행한다.
- `Ctrl + Alt + Esc`는 진행 중인 자동화 입력을 중단하는 긴급 정지 키다.

### 4.2 카카오톡 보안 로그인

- 사용자는 계정 별칭만 선택한다.
- 카카오톡 실행 파일과 대상 창이 로그인 화면인지 확인한다.
- 비밀번호는 실행 순간 Windows 자격 증명 저장소에서만 읽는다.
- 비밀번호는 클립보드를 사용하지 않고 대상 입력란으로 직접 보낸다.
- 대상 창이나 포커스를 확신할 수 없으면 입력하지 않는다.
- 계정 전환은 로그아웃 화면 진입 후 사용자 확인을 거쳐 로그인한다.
- 실제 계정 테스트 전에는 모의 입력 창으로 흐름을 검증한다.

### 4.3 문구·프롬프트 입력

- 일반 설정에 ID, 제목, 태그, 본문을 저장한다.
- 현재 입력란에 단문은 직접 입력하고 다중 행은 임시 클립보드를 사용할 수 있다.
- 임시 사용 전 클립보드를 백업하고 입력 직후 복원한다.
- 비밀번호 필드와 관리자 권한 창에서는 실행을 차단한다.

### 4.4 업무 모드

- 모드는 앱, 폴더, 웹사이트 항목의 순서 있는 목록이다.
- 실행 중인 앱은 중복 실행하지 않고 활성화한다.
- 한 항목의 실패가 뒤 항목 실행을 막지 않는다.
- 완료 후 성공·건너뜀·실패 항목을 요약한다.

### 4.5 창 정렬

- 현재 모니터의 작업 영역을 기준으로 좌측, 우측, 전체 화면에 배치한다.
- 다음·이전 모니터 이동을 지원한다.
- 최소 크기 제한이 있는 앱은 가능한 크기로 배치하고 실패를 기록한다.

### 4.6 파일 정리

- Windows 탐색기에서 사용자가 선택한 일반 파일만 받는다.
- 새 이름은 `YYYY-MM-DD_기존이름.ext` 형식을 사용한다.
- 원래 폴더 아래 `YYYY\MM`에 분류한다.
- 충돌 시 덮어쓰지 않고 `(2)`, `(3)` 접미사를 추가한다.
- 원본 경로와 대상 경로의 미리보기를 보여주고 확인 후 실행한다.
- 최근 성공 작업의 역방향 매핑을 저장해 한 번 되돌린다.
- 폴더, 숨김·시스템 파일, 선택하지 않은 파일은 제외한다.

## 5. 데이터와 보안 경계

| 데이터 | 저장 위치 | 로그 허용 |
| --- | --- | --- |
| 계정 별칭·자격 증명 대상 이름 | 일반 설정 | 허용 |
| 비밀번호 | Windows 자격 증명 저장소 | 금지 |
| 문구·업무 모드 | 일반 설정 | 본문은 기본 비기록 |
| 실행 결과 | 로컬 로그 | 비밀·클립보드 제외 |
| 파일 되돌리기 매핑 | 로컬 상태 파일 | 경로만 허용 |

첨부 대화에 노출된 기존 비밀번호는 어떤 산출물에도 복사하지 않는다. 사용자는 실제 사용 전에 해당 비밀번호를 변경한다.

## 6. 오류 처리

- 설정은 시작 시 검증하고 오류가 있는 모듈만 비활성화한다.
- 알 수 없는 명령, 중복 단축키, 누락된 실행 파일은 진단 결과에 표시한다.
- 카카오톡 대상 검증 실패는 입력 중단으로 처리한다.
- 파일 정리 도중 일부 실패가 발생하면 성공·실패 매핑을 분리해 보여주고, 성공 항목만 되돌릴 수 있게 한다.
- 로그 기록 자체가 실패해도 사용자 작업은 안전하게 중단하거나 계속할 수 있어야 한다.

## 7. 검증 전략

1. AutoHotkey v2 구문 검사
2. 설정 스키마와 명령 ID·단축키 충돌 검사
3. 모의 로그인 창에서 대상 확인·포커스·입력 중단 검증
4. 실제 비밀번호가 저장소·로그·클립보드에 없는지 검색
5. 문구 입력 후 클립보드 복원 검증
6. 업무 모드 중복 실행 방지와 부분 실패 검증
7. 단일·다중 모니터 창 배치 수동 검증
8. 임시 파일에서 미리보기·날짜 이름·충돌·되돌리기 검증
9. 사용자 화면에서 실제 자격 증명 등록과 카카오톡 로그인 최종 확인

TypeScript 프로젝트가 아니므로 `npx tsc --noEmit`은 실행 대상이 아니다. 대신 AutoHotkey 구문 검사와 관련 PowerShell 도우미의 파서 검사를 수행한다.

## 8. 하네스 구조

- `orchestrator`: 명령 등록, 모듈 호출, 상태·오류 통합
- `builder`: 작은 범위의 모듈 구현과 증거 기록
- `qa-reviewer`: 보안 경계, 파일 안전, 단축키 충돌, 회귀 검증

세부 실행 규약은 `docs/harness/manifest.md`, 역할 계약은 `docs/harness/agents/`에 둔다.

## 9. 진화 규칙

- 사용자 교정은 `tasks/lessons.md`에 패턴으로 기록한다.
- 같은 실패가 반복되면 회귀 테스트를 추가한다.
- 새 자동화는 명령 계약, 위험 수준, 실패 격리, 검증 절차가 있을 때만 등록한다.
- 변경 이력은 하네스 manifest에 날짜·대상·이유로 기록한다.
